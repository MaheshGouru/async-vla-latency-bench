# Episode Matching and Variant Freeze

## 0. Source artifacts used to freeze this protocol

This document was written after inspecting:

```text
stage1_resolved_variants.csv
latency_calibration_episode_results.csv
```

Important terminology:

- `stage1_resolved_variants.csv` is the exact Stage 1 LIBERO-Plus variant manifest.
- `latency_calibration_episode_results.csv` is the completed revised **Stage 0**
  latency-calibration result table. It is not the future Stage 2 manifest.

The completed Stage 0/1 MD files remain unchanged.

## 1. What the completed Stage 0 artifact establishes

The calibration table contains:

```text
tasks:
    goal_drawer
    long_stove_moka
    spatial_transport

methods:
    naive_async
    rtc

added_delay_ms:
    0,100,200,300,400

seeds:
    0,1,10,11,12,13

6 seeds per task × method × delay cell
180 total rows
```

Every row is marked `status=ok`.

Stage 2 must **not** silently reuse these rows as if they were new sensitivity
replicates.

## 2. Stage 2 matching rule

Stage 2 uses new seeds:

```text
SEEDS = [5,6,7,8,9]
```

Therefore Stage 2 episodes do **not** match Stage 0/1 by seed.

They match Stage 0/1 only at the level of:

```text
same checkpoint
same three base task identities
same RTC implementation
same control/timing semantics
same preprocessing/action representation
same hardware/runtime class where feasible
```

Within Stage 2, matching is strict:

> For a fixed `(task_key, seed)`, every horizon × delay condition must begin from
> the same base-task initialization generated by that seed, to the extent the
> environment API is deterministic.

Thus for one task and seed, all of:

```text
n_action_steps = 10,15,20,25,30,35
delay = Native,+100,+200,+300
```

must be paired on the same seeded initial condition.

Do not assign different initialization indices by horizon or delay.

### Stage 2 manifest must include

```text
task_key
suite
task_id
task_name
seed
initialization_index_or_id
initial_state_fingerprint
execution_method
n_action_steps
added_delay_ms
checkpoint_id
runner_commit
environment_version
```

If the environment exposes no explicit initialization index, record a stable hash
of reset-state fields as `initial_state_fingerprint`.

## 3. Why Stage 2 uses new seeds instead of Stage 0 seeds

This is deliberate.

The Stage 2 purpose is to test whether the frozen Stage 1 operating point is
locally stable on an **independent five-seed block** rather than merely reproducing
the six calibration seeds.

The Stage 2 `25/+200` cells therefore act as an out-of-sample replication of the
calibrated operating point.

Do not replace Stage 2 seeds with Stage 0 seeds solely to reuse rows.

## 5. Stage 3 episode matching rule

Stage 3 uses new held-out seeds:

```text
SEEDS = [14,15,16,17,18,19,20,21]
```

Therefore Stage 3 does **not** repeat Stage 1 episode seeds.

Instead, it repeats the Stage 1 **experimental condition definition**:

```text
same base task
same exact LIBERO-Plus variant identity
same perturbation family
same RTC implementation
same Native/+200-ms delay definition
same checkpoint
```

Within each Stage 3 condition, pair all horizons and delays by seed.

For fixed:

```text
task_key
variant_name
seed
scene ∈ {ID,OOD}
```

the following must share the same seeded reset state wherever the benchmark API
permits:

```text
n_action_steps = 20,25,30
delay = Native,+200
```

### ID versus OOD pairing

Do **not** require the OOD state to be geometrically identical to ID when the
perturbation itself changes geometry or robot initial state.

Instead match all **non-perturbed factors** and the seed.

Examples:

- `robot_initial_state`: different robot initial state is the perturbation; do not
  force it back to the ID state.
- `object_layout`: changed object layout is the perturbation; preserve that exact
  Stage 1 variant.
- `light_conditions`: geometry/reset should otherwise match the seeded base task.
- `sensor_noise`: underlying task/reset should otherwise match; noise configuration
  remains exactly the frozen Stage 1 variant.

## 6. Stage 3 manifest invariants

Before running, assert:

```text
for every OOD candidate:
    classification_id is exactly frozen
    api_task_index is exactly frozen
    variant_name is exactly frozen
    difficulty_level is exactly frozen

for every task/variant/seed/scene:
    all {20,25,30} × {Native,+200} rows exist
    same initialization identity is used across horizon/delay cells
```

Also verify that shared ID controls are reused logically across perturbations on
the same base task rather than rerun and counted as independent controls.

## 7. Stage 4 / VLASH matching rule

If VLASH is run:

```text
SEEDS = [22,23,24,25,26]
```

Use the **same exact OOD variant IDs carried into Stage 3**.

RTC and VLASH must be paired on:

```text
task
variant
seed
scene
delay
initialization identity
```

Only the execution method may differ.

If the official VLASH integration cannot preserve these semantics, fail the
compatibility gate rather than comparing unmatched episodes.

| Stage | Seeds | Match old episodes by seed? | What must be preserved |
|---|---|---|---|
| Stage 0 | `0,1,10,11,12,13` | completed | calibration provenance |
| Stage 1 | `0,1,2,3,4` | completed | frozen OOD variants |
| Stage 2 | `5,6,7,8,9` | **No** | same base tasks; strict within-stage task+seed pairing |

| Stage 4 | `22..26` | **No** | exact Stage 3/Stage 1 variant identity and matched RTC/VLASH episodes |

## 9. Core principle

Future experiments should replicate **conditions**, not recycle exploratory
episodes.

New stages use new seeds for independence, while task identities and selected OOD
variant identities remain frozen so that differences can be attributed to the
new experimental variable rather than a changed benchmark instance.
